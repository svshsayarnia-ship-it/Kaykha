# Kaykha Rule Engine

قوانین بازی نباید در رابط کاربری یا داخل یک تابع بزرگ پراکنده باشند.

## قرارداد معماری

- `public.kaykha_rule_catalog`: تعریف قابل‌نسخه‌بندی خانواده، کلاس و مود.
- `app_private.kaykha_round_effects`: دفتر خصوصی اثرهای اجراشده در هر راند.
- پردازشگرهای مستقل پایان‌راند: اقتصاد، مود، خاندان و AI.
- رابط کاربری فقط فرمان معتبر می‌فرستد و دفتر وقایع را نشان می‌دهد؛ قانون را محاسبه نمی‌کند.

## افزودن یا تغییر قانون

1. یک `rule_key` پایدار بسازید؛ مانند `family.مهران`.
2. زمان اجرا را مشخص کنید: `setup`، `negotiation`، `orders`، `resolution` یا `passive`.
3. اثر را در یک تابع کوچک و مستقل پیاده کنید.
4. هر اجرای موفق را با `app_private.record_kaykha_effect` ثبت کنید.
5. برای تغییرهای وابسته، trigger تازه نسازید مگر اینکه اثر واقعاً یک رویداد پایان‌راند باشد.

## مرزهای مهم

- قواعد محرمانه، هویت خائن و فرامین پنهان در `app_private` می‌مانند.
- هیچ کلید سرویس یا محاسبهٔ قابل‌اعتماد در مرورگر قرار نمی‌گیرد.
- تغییر متن راهنما یا UI نباید نتیجهٔ جنگ، اقتصاد یا مودها را تغییر دهد.
- هر قانون باید بتواند بدون بازنویسی بقیهٔ موتور خاموش یا نسخه‌بندی شود.
